# Experiment ledger

Every feature, optimization, and fork-local fix that has landed on `main`, and
what came of it. This is the human-readable index; the authoritative record is
the git history itself:

```bash
git fetch origin                     # main is a local ref; see AGENTS.md rule 13
git log --first-parent origin/main   # every experiment, one line each
git diff <merge>^1 <merge>           # exactly what one experiment changed
git log <merge>^1..<merge>^2         # how it was built
scripts/export-patch.sh <slug>       # a clean patch series against current upstream
```

Add a row when an experiment merges. Update `Result` once it has run on a real
node, including when the answer is "no measurable effect" or "made it worse".
A negative result that is recorded is worth more than one that is quietly
abandoned, because it stops the next person repeating it.

Two notes on the last two, because both are easy to read as something they are
not.

**`iceboxed` covers two different reasons** and the rows show both: #248 is
there because the idea **failed on its merits**, a slacker passes its proof
99.9% of the time, and #235 because it is sound but **outside what this fork
can change**, which its row says in as many words. The repository label reads
"sound but not worth doing now", which fits the second and not the first; the
rows are the authority here.

**`withdrawn` is not `reverted`.** `reverted` means `main` carried the change
and a later merge backed it out, so the behaviour shipped for a time.
`withdrawn` means the behaviour never reached `main` at all. Both remain
inspectable: fork branches are never deleted and merges are `--no-ff`, so the
commits that made and unmade a withdrawn change land on `main` too, which is
deliberate, since the point of recording it is that the next person can read
what was tried.
